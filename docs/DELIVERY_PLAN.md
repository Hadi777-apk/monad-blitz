## 2. 变化与范围

从 v0.2 的总体产品设计收缩到比赛实施版：合并 RewardVault 与 MiningCore 为 Mining；不做 B、注册目录、自动估价、转发服务、真实链外商品或争议裁决。通用交付规范保留为后续扩展设计，不给当前不可升级实例偷偷加权限。

轮次从固定全局时间窗改为一次一轮、开轮时间加轮长；积分从统一工作单位简化为每题 1 分；开轮预留、空轮关闭退回。不修改 1000 总供应和 800/200 划分。

未来引入 B 或链外商品需新实例/协议规则；重新发行必须公开资产身份，不能叫作迁移无法取出的旧 200。

## 3. 实现顺序与完成标准

1. 先 BLITZ、Mining 和最小网页：开轮、算题、链上接受、关轮、区间领奖。完成标准包含空轮、100 轮上限和直接合约交互。
2. 再 Escrow：签约、各入 P、NFT 真托管、原子交付、提现；同时完成两类超时、资金退款与授权 NFT 取回。不能把退款当选做。
3. 最后可选事件历史、榜单与外观。核心未跑通时不加更多品类或服务。

只演示测试网资产，不主网、不真实法币收款、不真实 Steam 托管。没有实现的功能明确写“设计中”，不拿模拟图片冒充真实项目运行。

## 4. 三人分工建议

| 角色 | 责任 |
| --- | --- |
| 客户端 | 矿场与订单页面、钱包签名展示、可见开/关/领奖动作、独立恢复与失败状态 |
| 合约 | 固定供应与预算、验题/区间、Escrow 状态与资金、授权与必要验证 |
| 集成与验证 | 测试资产、可选事件读取、链交互说明、故障/边界场景、演示准备 |

这里只是建议，不替队友认领工作。合约多签治理/外部裁决不在本版新增功能中。开发只能在用户明确开始且符合活动时间规则后进行。

## 5. 必须带进后续实现验收

| 类别 | 场景 |
| --- | --- |
| 游戏资金 | 8 个最小单位及 8 枚平分三份，随机贡献，R_A+E_A+U_A+C_A+200=1000 |
| 轮次 | 空轮回收、重复开/关、第 100 个有效轮、迟交、重复/跨实例答案、分批重复领奖 |
| 正常交易 | 双方各入 100，NFT 给买家，卖家可提 200；失败交付无余额/终态残留 |
| 时间边界 | 恰好 F/D；完整入金在 F 后仍能 D 前完成；终态不能被退出/完成再次记账 |
| 退款 | 买方单入超时、完整入金未交付超时，原出资方独立提现 |
| NFT 恢复 | 原地址拒收不影响退款，原卖家可换有效地址；越权改地址、过期/重放授权和重复取回均失败 |
| 资产与签名 | 重复 NFT、错误 tokenId/币种、双角色重复入金、链/合约/版本/nonce 错误或取消重放 |
| 无后台 | 网页/索引服务停用时独立客户端仍能执行链上既有权利 |
| 前端发布 | 入口/版本不缓存，资源内容哈希，失效分块恢复，旧标签页自动切换新构建 |

上述均未执行。文档算例通过不等于代码测试、压测或审计。未来代码审查遵守用户指定 Hadi777-apk/open-code-review 委托流程。
