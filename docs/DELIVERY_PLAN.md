日期：2026-10-17。当前仅设计与文档同步；尚未开始应用/合约实现，没有部署、压测或审计结果。

## 1. 已接受方向与本版设计选择

| 项目 | 方案 |
| --- | --- |
| 产品 | 千枚矿场 + 通用担保交易，两个资金独立的业务模块 |
| 三项要求 | 去中心化、可扩展性、安全性落实到权限、计算复杂度、退出与资产守恒 |
| 游戏经济 | 1000 BLITZ；A 800 / B 200；各 100 个有效轮；标准 300 秒、演示实例 60 秒 |
| A 新规则 | 合约验题与记分，任何人可关闭轮次，区间差额分配与独立领取 |
| B 边界 | 本地自报不能证明真实性；主要实例默认关闭奖励接入，保留预算 |
| 交易规则 | 买家 P 货款 + 卖家 P 押金；交付后押金可领，保护期与最终核验后付货款 |
| 交易首版 | 同链测试 ERC-721 + 单一测试支付资产，保护期 0 |
| 链外商品 | 标准字段、证明与争议接口先设计，不接真实皮肤或实物 |
| 权限 | 不可变核心/订单，多签仅管理有限的新增版本与可选服务 |
| 当前授权 | 继续设计并同步文档，先不写代码、不部署、不提交未完成作品 |

## 2. v0.1 到 v0.2 的替换

- 移除 A 的平台裁判签发挑战、整轮上报积分和 60 秒人工复核窗口，改为链上接受时刻与公开验算。
- 移除 A 的平台钱包白名单/30 人协议上限；少量受控测试只是验收安排，不是协议准入条件。
- 用贡献区间差额舍入替代最大余数排序，保证精确分完预算且不遍历全部参与者。
- 预算在首条有效贡献时预留，关闭轮次时确定分配，领取时实际支付；账本增加开放轮 E 项。
- 新增标准订单、双边入金、押金返还、交付适配器、保护期、争议和失联退出。

这是架构与极小单位舍入规则的更新，不是已发布合约的变更；目前没有需迁移的链上实例或用户资金。

## 3. 分阶段最小交付

| 阶段 | 应完成什么 | 验收边界 |
| --- | --- | --- |
| 0 当前 | 完整设计、信任边界、资金算例、验收清单 | 只有文档；用户明确开始实现后才进入下一阶段 |
| 1 挖矿核心 | A 开轮、验题、记区间、闭轮、领取，固定供应与两池隔离 | 平台服务停机仍能直接领取；B 关闭状态明确 |
| 2 交易核心 | 测试商品托管、双方签约各入 P、同链交付、押金/货款领取、超时取消 | 一次正常订单 + 一次未完整入金退款，无真实商品或资金 |
| 3 体验与公开 | 一个网页入口、矿场/订单状态、事件查询、规则与备用交互说明 | 正确区分预计/已确定/到账，公网可用、旧标签页能更新 |
| 4 选做实验 | 本地统计或链外证明模拟、基础外观与成就 | 显式标记模拟/自报/未接入，不能冒充真实交割 |

若当天无法完成两个核心闭环，公开说明实际完成范围；不以静态界面、模拟截图或计划代替已完成交易。B 不开放时不得把 A 的 800 枚说成全部 1000 枚可争夺。

首版不做主网、真实法币、充值、交易所、跨链桥、真实 Steam 托管、实物物流接入、付费算力加成或自建 Rollup。

## 4. 三人分工建议

| 角色 | 责任 |
| --- | --- |
| 客户端/体验 | 游戏与订单流程、钱包与签名展示、链上交易状态、备用交互入口 |
| 合约/安全 | 固定供应、A 验题区间分配、Escrow 订单状态与资金守恒、权限与关键测试 |
| 数据/集成 | 事件索引、可替换查询、估价规范、测试商品/支付资产接入、故障与演示准备 |

完整架构覆盖后续方向，不要求一天实现每种品类。分工未替任何队友认领任务，活动团队仍按本场最多 3 人规则。

## 5. 必要接口交接

- 实例地址、规则版本、链 ID 和部署清单统一，不能把同名不同实例混成一个资产。
- A 提交原始答案，不接后台任意积分表；贡献编号包含钱包归属与区间。
- 交易双方对相同订单签名，资产、价格、所有期限、核验规则与失联结果均完整固定。
- 金额统一整数最小单位；链上记为可领取与交易确认到账明确分开。
- 事件索引支持确认、重组、游标重建与分页；数据库不能作为资产所有权的唯一来源。
- 适配器不能改变 Escrow 金额/收款人，新增版本不影响旧订单；隐私证据不进入公共仓库。

## 6. 必须验证的场景

| 类别 | 验收 |
| --- | --- |
| 供应 | 无增发/团队提取路径，A≤800、B≤200；R+E+U+C=1000 |
| 游戏比例 | 60/30/10 分到约 4.8/2.4/0.8，区间尾差精确分完每轮预算 |
| 生命周期 | 空轮、首次预留、关闭延迟、最后有效轮、重复答案/领取、跨实例重放 |
| 去中心化 | 关闭后台、榜单、转发和数据库后，独立客户端仍可验算、闭轮、领取和执行到期订单动作 |
| 正常订单 | 双方各入 100，交付后卖家 100 可领，最终再得 100；无重复支付 |
| 失败订单 | 单方入金超时、交付失败、已退押金后撤回、争议和裁决失联的余额守恒 |
| 签名/权限 | 错链、错合约、过期/取消/重复签名、适配器越权、接收回调与恶意资产 |
| 数据/隐私 | 过期估价和假用量不直接决定提款；没有代码、密钥、会话或私有证据泄露 |
| 前端更新 | 入口/版本不缓存、资源内容哈希、失效分块恢复，旧标签页能自动更新 |

性能测试按少量并发起步，逐步增加钱包、答案和订单，记录确认延迟、成功率、费用、索引滞后与共享状态热点。没有实测前，不承诺任何具体 TPS、免费领取或几千人承载能力。

代码审查沿用用户指定流程；文档算例检查不等于代码审查、链上验收或安全审计。生产前须另做独立审计及真实品类验证。

## 8. 尚需在实现前落实的参数

起始计算难度、每笔贡献/领取批次上限、测试支付资产与商品合约、确认策略、各种超时长度、独立权限持有人和外部核验/争议服务尚未实测或选定。

用户确认的商品始终归买家、双边各付 P、交付后退卖家押金、保护期后付货款不变。外部品类无法接受失联风险分配时，不开放该品类入金；不临时扩大权限解决。
