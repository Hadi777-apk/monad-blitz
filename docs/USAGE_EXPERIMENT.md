# B：本地 Codex 用量自动分币实验

这是单独的本地实验，不修改 v0.5 A 矿场、Escrow 或原 BLITZ 中永久锁定的 200 枚。新合约 `UsageMining` 创建独立的 `UBLITZ`，一次性供应 200 枚；新资产不能称作旧资产的解锁或迁移。

## 已实现的流程

本次 Codex 聊天的 `event_msg/token_count` 累计统计 → 首次接入基线 → 新增非缓存输入加输出 → 固定上报者提交 → 每 1000 token 计 1 分、零头按钱包结转 → 60 秒轮截止 → 自动结算 → 自动代领到绑定钱包。

每个非空有效轮分配 2 UBLITZ，最多 100 个有效轮。沿用区间差额分配公式，全部贡献的奖励之和严格为本轮预算。空轮退回预留，不消耗有效轮名额。总量守恒为：剩余 + 开放轮预留 + 待领取 + 累计发放 = 200。

## 数据和信任边界

- 当前只接入部署时明确指定的一个本机 Codex 会话，不扫描其他聊天。采集程序提取累计输入、缓存输入和输出三个统计字段；不保存或上传聊天正文、代码、Cookie、密钥或提示词。
- 首次快照只作基线，不奖励历史总量。只读取 `total_token_usage`；不累加 `last_token_usage`。推理 token 已在输出中，不重复计数；缓存输入不计分。
- 重复快照不增加累计值，报告编号绑定链、实验合约、会话来源与累计值。来源钱包不可重绑。重启后以链上累计值和已领取标志去重，不能依赖本地文件“再发一次”。
- 累计值回退、日志截断或替换时暂停计奖，不能把异常当成新消耗。
- 本地日志可被用户修改；固定上报者可以虚报或拒报。因此这是可信本地采集器实验，不是服务商证明、去中心化工作量证明或官方账单。服务端核验尚未实现。
- 采集服务仅绑定 `127.0.0.1:8787`，只提供统计状态查询；Vite 通过 `/usage-api/status` 代理。链上仅提交来源哈希、钱包、累计有效量与报告哈希，不提交正文。
- 自动化使用 Anvil 的公开、已解锁开发账户，仅允许链 31337。不使用用户的钱包私钥，不请求新的 AI API，不额外产生付费模型调用。

## 本地运行

先保持 Anvil 在 `127.0.0.1:8545` 运行，并让它持续出块。构建和首次部署：

```powershell
forge build
node scripts/deploy-usage.mjs --source <本次Codex日志文件> --wallet <收款钱包> --session <会话ID>
node scripts/usage-collector.mjs
```

首次部署会创建独立实例并写入被 Git 忽略的 `cache/usage-config.json`。**恢复服务只运行采集器，不重新部署或重新建立基线。** 当前来源是部署配置指定的那一次聊天，新聊天需要显式接入并建立自己的基线。

网页打开 `http://127.0.0.1:5173/?chain=31337`，选择“AI 用量挖矿”。继续正常使用对应 Codex 聊天，新增有效用量进入当前轮；到期后自动到账，无需在钱包逐笔确认。不要为了演示额外购买或消耗 AI。

采集器停机后，已记录的奖励仍可直接调用链上 `closeRound()` 和 `claim(id)`，只能付给贡献原钱包。重启采集器会补做应完成的结算和领取。Anvil 没有保存状态时，重置本地链会清空本地演示资产。

## 验证

```powershell
forge test
node --test scripts/codex-usage.test.mjs
node scripts/verify-usage.mjs
```

合约测试覆盖：无历史补发、固定上报权限、来源绑定、重复报告、计数回退、跨来源/轮次零头结转、时间边界、重复领取、100 轮预算、加权舍入守恒。采集器测试覆盖缓存扣除、推理不重算、无关记录忽略、重复快照、半行写入、重启读取和计数回退。

本地验收（2026-10-17）：56 项合约测试、2 项统计解析测试和前端构建通过。已使用本次聊天的真实新增统计完成自动上报、结算与钱包到账；采集器重启后，链上报告编号与领奖编号无重复，新增累计量等于接入基线后的报告增量之和，200 枚预算守恒，原 A 钱包的 8 BLITZ 保留。可运行上述只读验收脚本，在固定区块重新核对；结果写入本地 `cache/usage-verified.json`。这不等于安全审计或服务端用量真实性认证。

字段口径参考 [OpenAI 用量说明](https://developers.openai.com/api/docs/guides/agents-api/observability)；本地日志字段以本机实际记录验证为准，不把它当作稳定的官方服务端计费接口。
