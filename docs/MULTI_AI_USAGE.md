## 本机统计

采集引擎使用 [junhoyeo/tokscale](https://github.com/junhoyeo/tokscale) 4.19.1（MIT），固定版本解析 58 类来源。实测这台电脑检出了 Codex、Claude、Pi、WorkBuddy 的本地记录。网页只显示实际读取的来源，不能把“未提供统计”当成 0，也不能保证覆盖所有网页版、所有账户或已删除的历史。

`collector/` 提供仅监听 `127.0.0.1:8788` 的本机服务。Windows 下载包包含 Node.js、Tokscale 和许可证，解压后运行 `start.cmd`，无需安装 npm 依赖。也可在该目录运行 `npm ci --ignore-scripts` 和 `npm start`。网页点“读取本机 AI 用量”；Chrome 首次可能要求用户允许访问本机服务。若不授权，在本机服务页面下载报告后，在网页“导入统计报告”。

本机累计显示输入、输出、缓存读取和缓存写入的总和；分币使用起点后的新增有效量（非缓存输入 + 缓存写入 + 输出），缓存读取不计奖励，推理不再次相加。Freebuff 的文本估算只展示、不计奖励。

首次读取为每个来源建立起点，历史用量不补发。新增来源第一次出现也只建立起点，避免突然导入旧日志产生历史奖励。重复读取、页面刷新或某来源暂时消失不会重算；累计数回退时暂停该来源新增计数，不减少已记分量。起点按活动、钱包、本机标识保存在当前浏览器，换浏览器或清除存储会丢失该起点。

## 隐私与真实性

采集器只返回来源名称和数字汇总，不返回模型名、会话 ID、工作路径、聊天、提示词、代码或密钥。命令使用显式 `--home` 禁用 Tokscale 的隐式 Cursor/Amp 云端同步，不运行 `usage`、`submit`、`login` 或 LLM 总结，不读取云端配额、不上传榜单。只有本地统计，不能证明服务商真实计费或阻止用户伪造；取消上限不改变这个信任边界。

本机接口只允许 GET，校验 Host 并只允许明确列出的网页 Origin，其他来源返回 403。报告只在浏览器解析，最终上链的是用户确认的新增整数 token 数。

## 发布与验证

前端生成 `version.json` 和内容哈希资源，入口与版本检查不缓存；已打开标签页每 15 秒以及恢复可见时检查版本。失效懒加载分块只自动恢复一次，避免重载循环。发布脚本保留旧资源并原子替换入口、版本文件。

部署前后验证包括：超过旧上限的用量可在新合约中记录、签名重放和时间边界、200 枚奖池守恒、多来源去重、缓存/推理口径、私密字段过滤、CORS/Host、Windows 便携包、旧标签页自动切换。统计详情与交易回执只保存在被 Git 忽略的 `cache/`。

本次顺便修复了公网源站 TLS 1.2 链路被重置导致的 CF 525：使用仅转发本域名到原 `127.0.0.1:31008` 的 Cloudflare Tunnel，未降低 HTTPS 校验模式。服务为 `monad-cloudflared.service`，专用令牌在服务器受保护目录，不写入仓库或命令行。
