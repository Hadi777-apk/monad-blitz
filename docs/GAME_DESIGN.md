# 千枚矿场：完整玩法设计 v0.2

状态：设计方案，尚未实现。日期：2026-10-17。A 改为链上验题与记分，B 保留为默认关闭的实验模式；另增加独立的 [通用交易协议](TRADE_PROTOCOL.md)。

## 1. 一句话介绍

全场只有 1000 枚宝石。玩家选择让浏览器完成计算挑战，或者把 AI 编程用量登记为贡献，在各自赛道按贡献占比领取宝石；积分结算和代币领取结果可以查询。

对外定位：有限资源争夺 + 开发者贡献可视化 + Monad 链上结算的多人小游戏。

借鉴比特币的有限总量、计算竞争和公开规则，不复刻比特币网络或共识。玩家计算用于游戏挑战，不参与保护 Monad 共识；AI 用量也不等于真实算力或代码质量。

## 2. 玩家目标与完整循环

1. 旁观：打开矿场，看到剩余奖励、当前倒计时、两赛道排名和最近领奖记录。
2. 加入：连接钱包，确认 Monad 测试网，看到游戏实例标识与规则版本。
3. 选择：进入「计算矿工」；「编程矿工·实验」只在明确标记且具备接入条件的实验实例开放，不把未接入按钮伪装成已可用。
4. 贡献：完成挑战或提交本轮新增 AI 用量；看到已接受积分和预计份额。
5. 等待结算：每轮结束后任何人可关闭轮次，按合约已接受贡献确定奖励，无需后台裁判批准。
6. 领取：玩家确认链上交易，奖励进入钱包；领取不影响下一轮参与。
7. 成长：获得外观、成就和个人记录，继续竞争剩余奖池。
8. 结束：某赛道 100 个有效轮次结束后停止分配；两赛道均结束后，矿场进入纪念展示状态，未领奖励仍可领取。

「预计奖励」随其他人参与而变化，未关闭轮次前不承诺具体数量。没有参与门票；提交答案、关闭轮次和领取等链上操作需要测试网 MON 手续费，实际成本尚未测量。

## 3. 模式 A：计算矿工，核心玩法

### 3.1 玩家看到什么

- 页面是一座共享矿场，玩家有一个矿工形象。
- 点击「开始挖矿」后，浏览器在明确授权下计算；找到有效答案时出现采到矿石的动画。
- 显示已验证矿石数、贡献积分、当前份额和本轮倒计时；本地计算速度只作参考，不直接决定奖励。
- 玩家可以随时停止；切换模式不会删除已接受的贡献。
- 默认一个计算任务，页面隐藏时暂停，提供低负载与停止按钮。不能把这些前端节制措施当作强制防作弊。

### 3.2 什么算有效贡献

- 挑战来自合约公开状态，包含链 ID、实例、规则版本、钱包、轮次、种子、难度与截止时间；任何人可在时间窗口内开启轮次，无需裁判签发。
- 玩家寻找一个 nonce，使挑战内容与 nonce 的 SHA-256 结果达到指定难度。
- 只有绑定正确、未到期、未重复、截止前被链上接受且哈希结果合格的答案才计分；本地找到或发给后台不代表已计分。
- 同一轮所有计算矿工使用相同难度 d；每个有效答案计 `2^d` 个工作积分，同轮多提交有效答案就多计分。
- 同一实例先固定难度；要改难度则用新规则实例，不改变已有轮次。
- 起始难度建议 d=16，属于待实测参数，不是已经验证的设备表现。首版先固定难度，避免临时调参影响公平。

这里证明的是完成了挑战，并非证明一台电脑使用了多少瓦电、运行了多长时间，也不证明计算产出了有用代码。设备更快通常能提交更多答案，但实际份额有波动。

### 3.3 让它成为游戏

- 每轮显示个人排名、距离上一名的积分差距和全场采矿进度，避免只有一个余额数字。
- 新手目标：第一个有效答案、完成第一轮、第一次成功领取。
- 持续目标：参与 3 个有效轮次、累计提交 10 个有效答案、完成两种模式体验。
- 合作目标：全场当轮有效答案达到预先公布的门槛，点亮矿场灯塔，获得当轮纪念成就；不额外增发奖励。
- 外观成长：累计已结算奖励达到 1、5、20 BLITZ 时解锁不同矿工外观。按历史获得量计，不因转账重复触发，不提供积分或经济加成。
- 排名和荣誉独立于买入或转入的代币余额。允许有更强的设备，不出售加速器。

灯塔初始门槛建议 100 个答案，部署前按演示设备测量确定，启动后固定；这是设计目标，尚无性能依据。

## 4. 模式 B：编程矿工，实验玩法

### 4.1 玩家操作

1. 明确选择接入本地统计；首个适配目标为 Codex，其他工具以后再加。
2. 展示实际将读取的统计字段和项目范围，由用户选择活动项目与本地数据来源。
3. 第一次连接建立基线，只统计连接后、游戏活动期间产生的新增用量，不导入历史总量。
4. 持续同步新增统计；本轮显示实际计入的用量、积分和实验奖池份额。
5. 停止接入后不再读取；已接受的统计按规则结算。

本轮仅设计，不读取任何人的本地记录，也不调用模型来消耗 tokens。

### 4.2 计分口径

- 有效 tokens = 非缓存输入 tokens + 输出 tokens；缓存命中部分不计入。
- 若来源的输入总量包含缓存命中，应先扣除缓存命中；输出中的 reasoning 等子项不得重复累加。
- 每累计 1000 个有效 tokens 获得 1 个编程积分；不足 1000 的余额留到该钱包下一轮使用。
- 不按模型价格、购买金额、代码行数或机器型号加权；AI 用量只是本模式的游戏代理指标。
- 各来源字段必须先完成映射确认，无法区分缓存或无法消除重复累计的来源先不计分。
- 断开重连不能重复使用历史增量；同一来源身份不能同时绑定多个钱包。

具体日志字段、累计快照和会话切换行为需要在活动开发阶段用脱敏样例确认，当前不声称已有可用适配器。

### 4.3 信任与隐私边界

- 本地文件、自制统计器、截图和用户签名都不能独立证明模型服务真实消耗。用户签名只能证明是谁提交了记录。
- 主要实例默认关闭 B 的奖励接入并保留 200 枚；另建自报实验实例必须标明固定证明方及信任限制，不依赖测试名单冒充真人或用量认证。
- 本地去重、增量检查、合理性检查只能减少低成本滥用，不能阻止有意伪造。
- 仅上传钱包、实例/轮次、匿名来源身份、记录编号、增量统计、时间窗等必要信息。不上链保存用量明细。
- 不上传代码、提示词、聊天正文、文件路径、API Key、账号令牌或原始日志。
- 本地来源身份采用本次游戏专用随机标识；匿名记录也不能宣称完全不可关联。
- 原始记录留在本地；服务端明细最多保留 7 天用于演示复核，公开的是按钱包汇总的积分与奖励。链上记录无法通过删除明细撤回。
- 玩家可以关闭模式 B，通过模式 A 正常参与；不要求额外购买 AI 额度。

模式 B 只能影响其 200 枚奖池，不能占用模式 A 的 800 枚。没有可靠数据接入时保持关闭；模拟数据必须在独立模拟界面标明，不能混入主要实例结算。精确轮次、贡献区间和舍入见 [分配规则](TOKENOMICS.md)。

未来可探索提供方签名用量证明等更强证据；在来源未提供这种能力前，不作相关承诺。

## 5. 两种模式如何相处

| 问题 | 规则 |
| --- | --- |
| 两边积分能否相加？ | 不能。计算工作量与 AI tokens 没有可信的统一换算关系。 |
| 能否同时参加？ | 在两个模式均已明确开放的实验实例可以，各自贡献与分配；主要实例 B 默认关闭。 |
| 能否转移奖池？ | 不能。空闲、模式关闭或参与人数少都不挪用另一赛道奖励。 |
| 有人开多个钱包怎么办？ | 不承诺完全防女巫。线性分配不加新人奖金、钱包保底或单钱包封顶，降低拆钱包的直接收益；实验 B 另做来源去重，但不能证明真人或消耗真实。 |
| 别人转给我代币能提高挖矿能力吗？ | 不能；只认可本轮有效贡献。 |
| 组队会不会多拿？ | 首版不做矿池与队伍分账，避免重复计分；以后可以只增加队伍展示。 |

## 6. 页面与交互状态

| 页面 | 必须能看到/完成的内容 |
| --- | --- |
| 矿场首页 | 1000 总量、两池剩余额度、两个独立有效轮计数、轮次时间、连接钱包 |
| 我的矿工 | 选择模式、开始/停止、有效积分、预计份额、拒绝原因 |
| 本轮榜单 | 按赛道切换、统计更新时间、当前名次；未结算有明显标识 |
| 结算与领取 | 已结算奖励、累计已领取、待领取、交易状态和区块浏览器链接 |
| 规则与透明账本 | 规则版本、实例地址、历史轮次、积分与分配表、资金状态、裁判信任说明 |
| 本地统计设置 | 接入说明、允许字段、基线、同步状态、断开与明细删除入口 |

必要异常状态：未连接、错误网络、MON 手续费不足、用户拒绝交易、连接中断、挑战过期、重复答案、用量不合格、本地找到但尚未链上接受、轮次待关闭、交易失败、奖池耗尽。

公网网页不能直接任意读取本地文件。后续接入方案需采用用户明确选择的文件或自愿运行的本地统计助手，并对网页来源与本地接口访问作限制；本轮不实现或安装任何助手。

## 7. 公平性与公开承诺

- 只按被接受的贡献计分，不按页面在线时间或前端自报速度计分。
- 有效答案不重复计分、过期挑战不计分、历史 AI 用量不重复计分。
- 前端榜单可能延迟，以最终链上结算和公开分配明细为准。
- A 的答案、去重与记分由合约执行，平台不能任意补写积分；链拥堵、区块排序和费用会影响及时纳入，不能承诺每个本地答案都有奖励。
- B 的用量真实性仍依赖证明来源；即使多签或提交摘要，也不能把本地自报变成真实消耗证明。
- 奖励按链上接受记录和贡献区间公式分配；后台不能事后修改已接受积分或追回已确定奖励。
- 实验模式没有代码质量认证、真人认证、绝对公平或投资收益承诺。

## 8. 游戏结束后

两池均结束后保留余额、历史战绩、外观与领取入口；若 B 未开放，其预算继续保留，不能宣称全部发完。矿场不加入代币销毁、质押生息或付费升级装备；独立担保交易模块不改变游戏供应和积分。

1000 枚只对应一个游戏实例；不通过重开赛季重置该合约额度。以后另建实验实例必须清楚显示新地址、新奖池，不得宣传成同一实例继续发行。
