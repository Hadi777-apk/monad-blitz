# 安全、信任与验收模型 v0.2

日期：2026-10-17。状态：设计要求；不是已实现能力、测试报告或安全审计。

## 1. 必须保护的东西

- 用户私钥、签名授权、订单资金与可领取余额。
- 固定 1000 BLITZ 供应，A/B 预算和已接受贡献。
- 商品身份、交付规则、保护期、核验者与争议退出约定。
- 玩家绕过项目服务读取状态和执行既有权利的能力。
- 本地代码、聊天、用量来源信息与非公开交付证据。

## 2. 谁可能作恶或失效

参与者可以用多个钱包、专业硬件、伪造本地日志、重复或重放请求；交易对手可以不交货、否认收货、撤回外部交易；报价源可能过期或被操纵；前端、转发、索引与 RPC 可以失联或误导。

项目运营方、管理员、外部核验者和裁决者也必须纳入威胁模型，不能默认它们永远诚实。多名签名者可能由同一实体控制，链本身也存在拥堵、审查、排序与短暂状态重组风险。

## 3. 权限矩阵

| 角色 | 可以 | 不可以 |
| --- | --- | --- |
| 玩家 | 提交绑定自己的有效答案、领取自己的奖励 | 任意设置积分或提取他人奖励 |
| 买卖双方 | 签署订单、入金、按约定提交事实/争议、签署共同和解 | 单方面改价、替换对手、重复获得退款和货款 |
| 任意调用者 | 按公开条件开启/关闭轮次、触发超时及固定收款人的结算 | 改条件、改收款人、凭调用身份获得别人资产 |
| 转发/执行服务 | 转发原始证明和按时调用合约 | 自报积分、独占执行权、持有用户私钥 |
| 外部核验者 | 为指定订单提交限定交付事实 | 修改金额、借证明提取其他订单资金 |
| 固定裁决者 | 在本订单可裁决余额内执行预先授权的分配 | 追缴已退押金、改变其他订单、无限延长裁决期 |
| 项目管理多签 | 发布新版本目录、管理可选服务及停止新增业务入口 | 升级改旧规则、抽走奖励/托管款、冻结所有既有领取与退出 |

首版链上核心不可升级。由此可能无法就地修复错误，不能声称可同时「管理员完全无权干预」又「管理员能无条件修复所有事故」。

## 4. 必须始终成立的资金与状态条件

| 编号 | 条件 |
| --- | --- |
| G1 | BLITZ 总量为 1000，A 预留/分配总额≤800，B≤200 |
| G2 | 游戏 R+E+U+C=1000，预算不因外部转入或转回而重置 |
| G3 | 同一答案只产生一条贡献，同一区间只领一次；区间完整且不重叠 |
| G4 | 每轮奖励区间求和精确等于该轮预算；空轮不分配、不除以零 |
| T1 | 单订单累计实际支付/退款 + 已记可领取 + 仍锁定 = 累计有效入金 |
| T2 | 买家货款与卖家押金分别归属；退款与支付不能重复消耗同一金额 |
| T3 | 商品、双方、金额、核验者、期限与 fallback 在双方签约后不可单方改变 |
| T4 | 争议只影响本订单尚未分配资金，不污染其他订单或游戏金库 |
| S1 | 签名绑定链、合约、版本、订单/动作、角色、nonce 与期限；使用/取消状态链上可查 |
| S2 | 客户端显示的确定余额来自链上责任记录；估价、榜单与日志不直接拥有提款权 |

统一按最小单位整数计算，乘除实现需有精度和溢出边界验证；任何外部调用前后的状态与实际到账资产都要核对。

## 5. 主要攻击与对应防护

| 风险 | 设计防护 | 仍有的限制 |
| --- | --- | --- |
| 重入、恶意接收回调 | 明确状态先后、重入保护、各方自行领取、限制接入资产与适配器 | 依赖后续正确实现与审计 |
| 恶意 ERC-20、转账税/重基准 | 首版只接单一已核对支付资产，拒绝未支持行为 | 标准接口不代表资产安全 |
| 签名重放/抢跑 | 域隔离 + nonce/已使用/取消状态 + 固定收款人 | EIP-712 单独不解决重放 |
| 偷抄答案 | 哈希绑定收益钱包、链与实例，不能更换受益人 | 交易排序仍影响确认及时性和微小舍入 |
| 伪造算力 | 验证答案，不相信速度、在线时长或后台填的分数 | 不抵抗更强硬件，不证明有用计算 |
| 伪造 AI 用量 | B 默认关闭奖励接入，自报实验显式隔离 | 去重、多签、哈希都不证明消耗真实 |
| 区块种子影响 | 公开可复算，固定规则，不用于随机奖品 | 种子有区块生产者/开启时机影响，不能保证无偏 |
| 链外假交付/假最终状态 | 订单固定事实来源、证明范围、争议与失联结果 | 外部核验者可串通或来源可出错 |
| 价格操纵/陈旧报价 | 来源/时间/币种/属性可查，双方签成交价 | 无法保证唯一公允价或成交流动性 |
| API/抓取滥用 | 地址与域限制、尺寸/超时/频率限制、SSRF 防护 | 链上交易仍需处理链上资源限制 |
| 隐私泄露 | 私钥不进服务端；本地统计最小字段；证据授权访问 | 链上地址与行为公开，不能保证匿名 |
| 管理钥匙丢失 | 核心无任意提款权，必要管理权限多签 | 多签本身仍可能失联或串通 |

## 6. 停服退出与数据可用性

- A 的挑战、贡献区间、归属与最终积分保存在链上，不把领取依赖放在平台私有数据库或私有证明文件里。
- 开源合约交互说明和备用界面属于交付；用户可以换 RPC/客户端触发公开操作，但仍需要网络可达、手续费和链正常执行。
- 订单状态与已记负债在链上。未完整入金、未交付超时、保护期结束及裁决失联，均有事先固定的可触发路径。
- 链外事实缺失不等于商品未交付。fallback 是双方同意的损失分配，不能保证外部商品与资金总能双向完美恢复。
- 订单完整签名条款双方各留副本；敏感证据保存授权副本与备份，不能只保留无法还原正文的哈希。
- 索引服务按确认状态处理事件并支持重组回退与重放；无索引时界面显示延迟，不能用旧缓存宣称新交易成功。

## 7. 隐私与本地密钥

- 服务端和仓库不收集钱包私钥、助记词、Steam 会话 cookie、AI 密钥、聊天或原始代码。
- 本地统计助手仅在用户明确同意后读取选择的统计来源；限定允许字段、来源网页和本地访问权限，避免任意网页调用本地接口。
- 项目公共文档不包含用户钱包密钥、Mojo 助手密钥或私有证据。对外发送/上传仍需在用户授权范围内。
- 开发、部署、管理和用户钱包分开；测试钱包不得被默认用于主网或真实资金。当前本地测试钱包不等于已部署的合约管理体系。
- 自报实验用量明细拟最多保留 7 天以供核对，原始内容留本地；链上公开记录无法随删除申请撤销。

## 8. 后续实现必须执行的验收

1. 比例、整数舍入、空轮、最后有效轮、预留未关闭、分批领取与随机输入下的资金守恒。
2. 重复答案/领取/订单、取消签名、跨链/跨实例重放、错误钱包/收款地址与截止边界。
3. 关闭平台网页、转发、榜单和数据库，仍可通过独立客户端完成 A 领取与已约定订单退出。
4. 双方各入 P、单方未入、交付失败、退押金后撤回、最终付款、争议拆分和裁决失联；不能重复转出同一资金。
5. 恶意 token/资产回调、适配器越权、错误金额、权限角色和失败交易的状态一致性。
6. 不同参与数量/答案数/订单数下的手续费、延迟、吞吐、共享状态热点与存储成本；不能只看链的峰值 TPS。
7. 估价过期/来源冲突/链接滥用，核验者故障/假证明/延迟证明，证据缺失与隐私检查。
8. 前端旧标签页切换新构建、过期资源恢复、错误链、签名内容展示与交易失败提示。

这些验收尚未执行。代码审查必须遵守用户指定的 Hadi777-apk/open-code-review 委托流程；测试、文档检查和单纯跑 preview 均不等于完成代码审查。生产前还需要独立安全审计，比赛测试网演示不能冒充生产验收。

## 9. 上线范围与不可隐瞒的限制

首版仅测试网、小规模、有明确资产和适配器范围。原 v0.1 的 30 钱包白名单不再作为 A 的协议条件；先做少量参与者测试，不把人数上限当作去中心化能力证明。

协议目标是减少平台掌控资金和单方改规则的能力，不承诺所有链外事实都去中心化、不承诺无漏洞、不承诺没有任何停机风险。真实商品接入、资金规模扩大和主网部署不在本轮授权中。
