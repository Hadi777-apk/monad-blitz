# BLITZ 分币规则 v0.5

日期：2026-10-17。设计文档，尚未发行或部署。与 [比赛架构](ARCHITECTURE_v0.5_hackathon.md) 同步。

## 1. 总量与 B 的含义

- 初始化发行 1000 BLITZ，18 位小数，全部进入 Mining。
- A 支付预算 800，100 个非空有效轮，每轮 8。
- B 的 200 在此不可升级实例永久锁定；没有 B 轮次、积分、提款、救援、启用或迁移路径。
- 未来 B 新实例必须明确自己的资产来源和供应，新发行不能称为迁移旧 200。
- 不提供后续增发、销毁、转账税或团队预留。游戏与订单资金隔离，成交不奖励额外 BLITZ。

## 2. 串行轮次与预算

同一时间只有一个未关闭轮次。开轮要求 A 的非空有效轮数 k 小于 100 且无未关闭轮，预留 8 枚；截止为开轮区块时间加部署时固定的轮长。演示 60 秒，普通 300 秒。

提交只在当前时间严格小于截止时有效；关闭从当前时间大于等于截止开始。链上纳入时刻为准，本地完成、后台收到和待打包都不等于已接受。

- 空轮：关闭后 8 枚退回 A 可用预算，k 不增加。
- 非空轮：关闭后 k 加 1，预留 8 枚变成该轮已确定奖励。
- 关轮不等待玩家全部领完；下一轮可在关轮后开始，旧奖励继续有效。
- k=100 后不能再开轮；没人在场关闭时任何用户可自行关闭，不依赖运营方。
- 没有人发交易，合约不会自行开/关轮。串行轮的关闭延迟会推迟下一轮，不承诺精确 500 分钟全部完成。

与旧 v0.2 不同，本版开轮预留预算，不在首条答案时预留；名额只在非空轮关闭时消耗。

## 3. 每个答案 1 分

SHA-256 输入绑定链 ID、Mining 实例、轮次、种子、钱包、nonce。达到固定前导零阈值、未过期、未重复且被链上接受，统一获得 1 分；多余前导零不加分。

难度暂定 16 位，部署前实测再固定。同一难度下，统一 1 分与统一给予 2^16 个预期工作单位的占比相同；代码和界面只需要 1 分。后台不能补写任意分数。

每条贡献记录一个连续区间 `[S,S+1)`，S 为接受前的总积分，记录归属钱包与轮次。种子不是无偏随机证明；设备更强通常能更快找到答案，不保证人人平均分，也不保证有效计算带来有用业务产出。

## 4. 精确分配

令 B 为本轮 8 BLITZ 的整数最小单位，T 为非空轮关闭后的最终总分：

`本条奖励 = floor(B×end/T) − floor(B×start/T)`。

贡献区间不重叠且完整覆盖 `[0,T)`，全部相加恰好是 B。空轮不执行除法。每条奖励与其精确比例之差小于一个最小单位，链上顺序影响极小尾差，不增加总预算。

单条计算不遍历全场，领取按贡献编号处理；批次有界。实现需使用足够精度的整数乘除，不能浮点计算或忽略溢出。

| 8 枚分给三个依次接受的等分贡献 | 实际 BLITZ |
| --- | ---: |
| [0,1) | 2.666666666666666666 |
| [1,2) | 2.666666666666666667 |
| [2,3) | 2.666666666666666667 |
| 总计 | 8 |

若 10 个答案中 Alice 6 个、Bob 3 个、Charlie 1 个，分别约得 4.8、2.4、0.8，按实际区间处理最小单位。唯一参与者获得本轮 8 枚；没有按钱包保底、加速付费或新人奖励。

## 5. 领取

任何人可以触发某贡献的领取，但只能付给已记录的钱包，不能改收款人。记录只消费一次，交易失败不能留下已领取标记。无领取过期时间，网页/索引关闭不取消权益。

当前业务只有 A，不显示 B 可挖或实际发完 1000。A 完成后最多累计支付 800，B 的 200 仍然锁定。用户转回 Mining 的资产不恢复已使用预算，外部误转也不扩大预算。

## 6. 守恒

定义 R_A 为 A 尚可用于开轮的预算，E_A 为当前开放轮预留（0 或 8），U_A 为已关闭轮尚未领取，C_A 为 A 累计实际发放，L_B 固定为 200：

`R_A + E_A + U_A + C_A + L_B = 1000`。

`U_A + C_A = 8×k`，其中 0≤k≤100；C_A≤800。初始 R_A=800，其余 A 项为 0。空轮关闭 E_A 转回 R_A，非空关闭 E_A 转入 U_A，领取 U_A 转入 C_A。

A 全部完成并关闭时 R_A=E_A=0，U_A+C_A=800，L_B=200。此处是预算责任，不是所有用户当前余额的加总，不受后续转账重置。
