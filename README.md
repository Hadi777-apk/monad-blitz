# Blitz Mine · 千枚矿场

一个拟部署在 Monad 测试网上的项目，包含「千枚矿场」和「通用担保交易协议」两个独立业务模块：可验证贡献分配固定游戏奖励，标准订单承载不同类型商品的托管交易。

**当前阶段：架构方案 v0.2；只有设计文档，尚无应用代码、合约部署、性能验证或安全审计。**

## 一分钟了解

- 游戏代币暂名 `BLITZ`，总量固定为 1000 枚；不是 BTC，也不是 Monad 官方 MON。
- 800 枚用于可验证计算挑战，200 枚用于实验性编程用量模式；两个奖池独立计分。
- 标准轮次为 5 分钟，每个奖池各有 100 个有效分配轮次，每次分别分配 8 枚、2 枚。
- 同一奖池、同一轮内，按有效积分占比分配；空轮不消耗额度。
- A 赛道改为合约验证答案和记录贡献，任何人可按规则关闭轮次、领取自己的奖励；后台不能填写积分。
- B 本地 AI 用量仍可伪造，默认不开放有经济奖励的真实接入；200 枚预算保留，不能转给 A 或管理员。
- 交易按「买家货款 P + 卖家押金 P」托管：核验交付后退卖家押金，保护期结束再付卖家货款；失败、撤回及争议按订单约定处理。
- 估价是有来源、有时间戳的参考；成交价由双方签名确认。交易没有随机分配商品的环节。
- 游戏奖励、买家货款、卖家押金相互隔离；交易不强制使用 BLITZ，也不增加 1000 枚供应。
- 不出售挖矿加成，不做充值炒币、代币交易所或收益承诺。首版仅测试网资产演示。

以上均为拟议规则，不代表已有实现。参数在正式部署前可以讨论修改，启动后按该实例冻结的规则执行。

## v0.2 的重要变化

- 替代原 v0.1 的「中心裁判签发挑战、上传整轮积分」机制；A 的答案与积分以合约为准。
- 为避免结算遍历所有玩家，舍入改为贡献区间累计差额法，替代最大余数排序；精确规则及算例见代币文档。
- 去掉 A 的平台钱包白名单和 30 人协议上限；首轮测试人数仍需有界，性能必须实测，不能宣称无限容量。
- 加入通用交易；现有订单绑定的规则和核验方式不能被平台后台升级替换。
- 链外核验和实验用量仍有可信来源限制；不能把整个项目宣传成完全无信任系统。

## 比赛边界

活动前只进行调研与方案规划；项目开发在活动正式时间内开始。目标是在 Monad 测试网上完成一个公开可访问、能现场演示的原创应用原型。
